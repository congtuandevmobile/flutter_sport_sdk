# WorkoutEngine.kt

**Path:** `android/.../WorkoutEngine.kt` · **Layer:** native engine

Owns ONE workout: a `WorkoutSession` of the shared core and its journal, under one lock. THE rule: every event the core returns is appended to the journal (and synced) BEFORE the snapshot that shows its effect is published, so a number on the screen is never ahead of the disk. A failed write does not stop the workout but `journalFailed` becomes true and STAYS true; a workout that cannot write its first line is not started (`JOURNAL_WRITE_FAILED`). `start` is refused with `SESSION_OPEN` while another workout is running or paused; a command or sample for another session id is dropped (`NO_SESSION` for a command, silently for a sample). Samples are stamped with their real time (now minus `ageMs`). Time is the monotonic clock plus a shift: after `restore` the clock continues from the last journal event even if the phone rebooted (the monotonic clock restarted lower), so a restored workout can always resume. `restore` rebuilds the workout from its journal, PAUSED, and appends the recovery Paused event; it does nothing when the engine already runs that session and is refused with `SESSION_OPEN` while ANOTHER workout is running or paused, and restoring again from the extended journal gives the same workout. A snapshot is published about once per second and on every change. The workout belongs to the plugin instance: it stops being fed when the Flutter engine goes away (a process-wide owner is not built).
