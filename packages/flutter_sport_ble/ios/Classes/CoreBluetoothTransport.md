# CoreBluetoothTransport.swift

**Path:** `ios/Classes/CoreBluetoothTransport.swift` · **Layer:** native radio

The real radio. The `CBCentralManager` is created on first scan or connect, so the Bluetooth permission prompt appears then and never at launch (`adapterState` reads `CBManager.authorization` without creating it). A scan or connect requested before the adapter is powered on waits for `poweredOn`. Per device: discover services, then characteristics, subscribe to the wanted ones; a characteristic that cannot notify or whose subscription was refused goes to `failed` and is reported, the link stays. After `onReady` it reads once the wanted characteristics (battery, device information), one at a time. A link we cancel is tracked until its `didDisconnect` arrives, and a new connect to the same device waits for it, so a callback of the OLD link is never taken for the new attempt (every delegate callback also checks that the peripheral is the one of the current link). Adapter off, unauthorized or unsupported ends the links with `BLUETOOTH_OFF:` / `PERMISSION:` / `UNSUPPORTED:`. Not unit-tested (it needs a radio); never run against a real sensor. No reconnect, no state restoration.
