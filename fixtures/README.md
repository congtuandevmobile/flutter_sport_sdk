# Protocol fixtures

Packets the parsers are tested with. Every fixture says where it comes from:

| Origin | Meaning |
|---|---|
| `spec` | built by hand from the field layout of the Bluetooth SIG specification (the golden packets in `packages/flutter_sport_ble/sensor-core/src/commonTest`) |
| `device` | captured from a real device (model and firmware written next to it) |
| `synthetic` | generated by a test to provoke a case (rollover, reset, silence) |

Today every fixture is `spec` or `synthetic`: **nothing was captured from a real device**, so no protocol is marked verified. The
size of the FTMS Resistance Level field and the step and stair climber layouts in particular need a real machine.

Layout for captures (add as they exist): `fixtures/<protocol>/<device>-<firmware>.hex` with one packet per line, a `#` header with
the origin, the device and the date, and the expected metrics next to each packet.
